```python
# budget.py:285-299
def effective_compute(flops_used, residual_wall_time_s, lambda_flops_per_second=DEFAULT_LAMBDA_FLOPS_PER_SECOND) -> float:
    return float(flops_used) + float(lambda_flops_per_second) * float(residual_wall_time_s)

# budget.py:302-319
def is_combined_budget_exhausted(flops_used, residual_wall_time_s, flop_budget, lambda_flops_per_second=DEFAULT_LAMBDA_FLOPS_PER_SECOND) -> bool:
    if flop_budget <= 0:
        return False
    return effective_compute(flops_used, residual_wall_time_s, lambda_flops_per_second) > float(flop_budget)

# budget.py:322-326
def score_multiplier(effective_compute: float, flop_budget: float, *, failed: bool) -> float:
    """Per-MLP multiplier: 1.0 on failure (or no budget), else ``max(0.1, C/B)`` — uncapped above."""
    if failed or flop_budget <= 0:
        return 1.0
    return max(0.1, float(effective_compute) / float(flop_budget))
```

## A4. Runners, transport, worker lifetime, CPU/threads, environment

**There is no docker runner in whestbench.** `cli.py:1209-1213`: `--runner` choices `("local", "subprocess", "server", "inprocess")`; `_normalize_runner_name` (1793-1799) maps `server→subprocess`, `inprocess→local`; `cli.py:2968-2969`: `runner = LocalRunner() if normalized_runner == "local" else SubprocessRunner()`. Docker assets live only in `F:docker/` (see B2). The AIcrowd grader itself (`whestbench-evaluator`, referenced at `W:src/whestbench/validation.py:16-17` "TODO(evaluator-parity): align ... with the current whestbench-evaluator/worker/ingestion.py") is not in either repo.

**LocalRunner** (`runner.py:142-250`): `start()` loads the estimator via `load_estimator_from_path` and calls `estimator.setup(context)` in-process; setup time is measured after the fact: `if setup_elapsed > limits.setup_timeout_s: raise RunnerError("setup", RunnerErrorDetail(code="SETUP_TIMEOUT", ...))` (189-197). Memory limit is advisory: logs `"memory_limit_mb=%d is advisory in --runner local: enforcement requires --runner subprocess (uses RLIMIT_AS) or external sandboxing (cgroups)."` (163-168). `predict()` re-raises `BudgetExhaustedError`/`TimeExhaustedError` unchanged and wraps anything else as `RunnerError("predict", code="PREDICT_ERROR")`. `last_predict_stats()` returns None (scoring falls back to the host BudgetContext).

**SubprocessRunner** (`runner.py:256-570`): spawns `[sys.executable, "-m", "whestbench.subprocess_worker"]` (268-269) with `stdin/stdout/stderr=PIPE, text=True, bufsize=1, env=self._worker_env()` (292-300); `_worker_env` = `dict(os.environ)` plus `PYTHONPATH` prefixed with the whestbench `src` root (565-570). Transport is **JSON lines over the worker's stdin/stdout pipes** (`_send_request`: `json.dumps(payload)+"\n"`, 501-514; `_read_response` reads one line in a daemon thread with `join(timeout)`, 516-546). Requests: `{"command":"start", "entrypoint":{file_path,class_name}, "context":{width,depth,flop_budget,api_version,scratch_dir,submission_dir,seed}, "wall_time_limit_s", "memory_limit_mb"}`, `{"command":"predict","budget":int,"mlp":{"width","depth","weights":[w.tolist()...],"seed"}}` (weights are serialised as nested JSON lists per MLP — `_mlp_to_payload`, 133-139), `{"command":"close"}`. Setup response must arrive within `limits.setup_timeout_s` (327-334 → `SETUP_TIMEOUT`); note the 5 s window starts when the start request is written, i.e. it includes the worker interpreter start-up and imports plus `setup()`. Predict response timeout `_predict_response_timeout_s` = `max(predict_timeout_s(30), wall_time_limit_s + 5.0)` (37, 82-91) → `PREDICT_TIMEOUT`, process killed. Worker death codes `{"WORKER_EOF","WORKER_BROKEN_PIPE","WORKER_IO_ERROR","PREDICT_TIMEOUT"}` (42-44) mark the worker dead; the NEXT `predict()` calls `_restart_after_worker_death()` → `start()` again (re-running `setup()`, 365-377, 389-404). Response statuses: `ok` (predictions as `arr.tolist()`, plus `flops_used`, four timing fields, `budget_breakdown`), `budget_exhausted` → re-raised as `flops.BudgetExhaustedError`, `time_exhausted` → `flops.TimeExhaustedError`, `error` → `RunnerError(PREDICT_ERROR, details, traceback)` (447-463).

**One worker serves the whole suite; state is not reset between MLPs.** `main()` in `subprocess_worker.py:151-229` is a single loop over stdin: one `start` (load + `setup()`), then N `predict`s against the same estimator instance, then `close` (`teardown()`). Per MLP the worker builds its own `flops.BudgetContext(flop_budget=budget, wall_time_limit_s=wall_time_limit_s, quiet=True)` (66-70), calls `estimator.predict(mlp, budget)`, materialises inside the window, `del predictions` inside the window (84, so finalisers are billed), then validates outside (86). Memory cap: before importing participant code, `_resource.setrlimit(_resource.RLIMIT_AS, (limit_bytes, limit_bytes))` with `limit_bytes = memory_limit_mb * 1024 * 1024` (174-184; 8192 MiB by default); on platforms without RLIMIT_AS it writes a warning to stderr and continues.

**flopscope transport (what the grader uses)**: the worker simply `import flopscope` — whichever distribution is installed. With the in-process `flopscope` package the numpy work happens in the worker itself. With `flopscope-client` installed instead, every op is a ZMQ REQ/REP round-trip (msgpack) to a `flopscope-server` process that holds all arrays and does all numpy work; the participant process holds only `RemoteArray` handles (`F:flopscope-client/src/flopscope/_connection.py:16-17`: `_DEFAULT_URL = "ipc:///tmp/flopscope.sock"`, `_DEFAULT_TIMEOUT_MS = 30_000`; URL from env `FLOPSCOPE_SERVER_URL`, line 35; `tcp://host:port` also supported). The server is a single-threaded `zmq.REP` loop (`F:flopscope-server/src/flopscope_server/_server.py:154-178`), one session (budget) at a time; arrays/generators live in a `ConnectionStore` for the lifetime of the server process, surviving `budget_open/budget_close` (`_connection_store.py`, `_session.py:38-43, 227-231`): "module-level / setup()-time handles survive across MLPs (issue #107)". Caveat: whestbench's own code calls `flops.BudgetContext(..., wall_time_limit_s=...)` and `flops.namespace(...)`; the client `BudgetContext.__init__(self, flop_budget, quiet=False, namespace=None)` (`F:flopscope-client/src/flopscope/_budget.py:311-316`) has no `wall_time_limit_s`, and `namespace` is in the client's `SERVER_ONLY` set (`_server_only_data.py:330`). So whestbench as shipped runs against the in-process library; the evaluator's client/server wiring is outside these repos.

**CPU pinning**: no `taskset`/`cpuset`/`sched_setaffinity`/vCPU-split configuration exists in either repo (grep over all `.py/.md/.mdx/.yml/.toml/.sh`). The only resource statements: `W:docs/reference/estimator-contract.md:135` "8 GB — the allocation your Solution's own process gets on the grader; the instance has 64 GB in total, the rest going to the flopscope backend and the harness"; `F:docker/docker-compose.yml` demo participant container `cpus: 1.0`, `mem_limit: 256m`, `pids_limit: 50`, `network_mode: none`, `read_only: true`, `cap_drop: [ALL]`, `tmpfs /tmp:size=10m`. The "2 vCPU solution / 14 backend" split is not documented in these sources.

**Thread control**: `W:src/whestbench/concurrency.py:26-31` `_THREAD_ENV_VARS = ("OMP_NUM_THREADS","MKL_NUM_THREADS","OPENBLAS_NUM_THREADS","VECLIB_MAXIMUM_THREADS")`; `apply_thread_limit(n=None)` (34-69) reads `WHEST_MAX_THREADS` only when `n is None`, sets those four env vars and calls `threadpoolctl.threadpool_limits(limits=n, user_api="blas")`. **Cost formulas, quoted from source** (all per call; batch dims multiply):

Contractions (`_flops.py:217-246`): `matmul_cost(m, k, n) = max(einsum_cost("ij,jk->ik", [(m, k), (k, n)]), 1)` which "equals `2 * m * k * n - m * n`" (FMA=2: K mults + K−1 adds per output); `einsum_cost` (42-101) = whole-expression accumulation `total = (k-1) * prod(M) + prod(alpha)` with symmetry/aliasing awareness (`_accumulation/_cost.py`). `matmul`/`dot`/`inner`/`outer`/`tensordot`/`vdot` all route through `_einsum_routed_binary` → `_resolve_cost_and_output_symmetry(subs, a, b)` (`_pointwise.py:5528-5703`), with subscripts: matmul `"...ij,...jk->...ik"`, `"...mk,k->...m"`, `"k,...kn->...n"`, `"i,i->"` (5760-5812); dot 2-D `"ij,jk->ik"` (5705-5758); inner 2-D `"ij,kj->ik"` (5815-5861); outer `"i,j->ij"` with aliasing preserved (`a_orig_is_b_orig = a is b`, 5863-5951). **Aliasing is by Python object identity**: `_identity_pattern` groups operand positions with equal `id(op)` (`_einsum.py:25-42`; `_accumulation/_public.py:28-39`). Consequently `X.T @ X` (the `.T` view is a distinct object) is billed at full price, while `fnp.einsum("ji,jk->ik", X, X)`, `fnp.inner(X, X)`, `fnp.einsum("ij,kj->ik", X, X)` and `fnp.outer(v, v)` get the symmetric-output discount (M = n(n+1)/2). On the server, two client handles for the same array resolve to the same stored object (`_request_handler.py:664-712 _resolve_arg` → `session.get_array(handle)` dict lookup), so the same rule holds on the grader.

Pointwise (`_flops.py:104-126`): `analytical_pointwise_cost(shape, symmetry) = prod(shape)` or `unique_elements_for_shape(symmetry, shape)` for a `SymmetricTensor` (orbit count, e.g. n(n+1)/2 for a symmetric matrix); multi-output ufuncs (`divmod, frexp, modf`) bill `nout × numel`. Reductions: `analytical_reduction_cost` = orbit-mapped `numel(input) − numel(output)` (129-169; `_counted_reduction`, `_pointwise.py:3445+`); `cumsum`/`cumprod` = `_counted_reduction` (4485-4486), i.e. `numel − num_output_slices`; `mean` = reduction + one divide per output orbit (`_counted_mean`, 4257-4300); `var/std` = `2*pointwise + reduction(op_factor=2, extra 2M)` ≈ 4×numel (+M sqrt for std) (4372-4391); `nan*` reductions add one `numel` isnan pass on float/complex input. `where(cond, x, y)` bills `numel(broadcast)` under op `where` at weight 4.0 (= 4×numel), 1-arg `where` bills as `nonzero` (`_array_ops.py:1145-1206`). `allclose = 7·numel − 1`, `isclose = 6·numel` (`_counting_ops.py:130-160`; cost-model.md). `sort/argsort = num_slices × n × ceil(log2 n)` at weight 4 (`sort_cost`, `_flops.py:267-282`; `_sorting_ops.py:30-99`).

Linalg (`numpy/linalg/_decompositions.py`): `cholesky_cost(n) = max(n**3 // 3, 1)` (22-39); `qr_cost(m, n, mode)`: `k=min(m,n); factor = 2*m*n*k - 2*k**3 // 3`, ×2 for `reduced/complete`, ×1 for `r/raw` (68-80); `eig_cost = 25*n**3` (139-158); `eigh_cost = 9*n**3` (191-209, "dsyevd, includes runtime scaling"); `eigvals_cost = 10*n**3`; `eigvalsh_cost = 4*n**3 // 3`; `svdvals_cost = svd_cost(..., with_vectors=False)`. `_solvers.py`: `solve_cost(n, nrhs=1) = max(2*n**3 // 3 + 2*n*n*nrhs, 1)` (34-54; `symmetric` ignored); `inv_cost(n, symmetric)`: `n**3 // 3 + n**3` if symmetric (input is a `SymmetricTensor`, 139-143) else `2*n**3` (104-127); `lstsq_cost = svd(with vectors) + matmul(k,m,c) + k*c + matmul(n,k,c)` (173-222); `pinv_cost = svd(with vectors) + k + n*k + matmul(n,k,m)` (281-318). `_flops.py:178-214 svd_cost(m, n, k=None, *, with_vectors=False, full_matrices=False)`: `a,b = max,min; economy = 6*a*b*b + 20*b**3 if with_vectors else 2*a*b*b + 2*b**3`; full U when `full_matrices and m != n`: `4*a*a*b + 22*b**3`; top-k `1<=k<b`: `min(4*m*n*k, economy)`. `_properties.py`: `trace_cost(n) = max(n,1)` (25-43); `det_cost = 2*n**3//3 + n` (89-108); `slogdet_cost = 2*n**3//3 + 18*n` (142-161); `norm_cost`: `2*numel` for fro/L1/Linf/vector norms, values-only SVD for `ord in (2,-2,'nuc')`, `18*numel+16` for general-p vector norms (207-253). `_compound.py:132-165 matrix_power_cost(n, k) = (floor(log2 k) + popcount(k) − 1) × matmul_cost(n,n,n)`, negative k adds one `matmul_cost`. FFT (`numpy/fft/_transforms.py`): `fft_cost(n) = 5*n*ceil(log2 n)` (28-47), `rfft_cost(n) = 5*(n//2)*ceil(log2 n)` (50-70), `fftn_cost(shape) = 5*N*sum(ceil(log2 d_i))` (73-99).

Random (`numpy/random/_cost_formulas.py`, `__init__.py`, `_counted_classes.py`): continuous/discrete samplers `flop_cost = numel(output)` billed at the **output dtype** (float64 default → rate 2; `standard_normal(..., dtype=float32)` → rate 1) times weight (16 for normal/standard_normal/randn/exponential/gamma/..., 1 for `random`/`rand`/`random_sample`/`integers`/`randint`); `uniform = 3*numel` (`_uniform_cost`, 268-270: "uniform draws + affine map low + (high-low)*U"); `choice`: `numel(output)` with replacement (+`3n + draws*ceil(log2 n)` when `p` given), `n` without replacement, `sort_cost(n)` with `p` and no replacement (154-184); `permutation/shuffle = shape[axis]` (76-111); `multivariate_normal = svd_cost(d,d,with_vectors=True) + 2*N*d*d + 16*N*d` (241-255). Generator methods are wrapped per registry entry via `_make_counted_method` (`_counted_classes.py:27-116`; cost formula applied to the actual result); `default_rng(seed)` returns a counted `numpy.random.Generator` subclass (PCG64 via numpy) — free, deterministic per seed; `spawn` stays counted.

Stats (`stats/_base.py:54-123`): `flop_cost = cost_per_elem * max(numel(broadcast(x, params)), 1)`, `x = np.asarray(x, dtype=np.float64)` (so rate 2 always; a float32 input also emits a `FlopscopeWarning` about promotion); per-element constants (`stats/_norm.py:197, 230, 263`): `norm.pdf 27`, `norm.cdf 48`, `norm.ppf 83`; `truncnorm.pdf 28 / cdf 51 / ppf 81`; others in cost-model.md "Stats" table. **There is no `erf` op** (not in either registry); the client's `__getattr__` error text points to "erf via flopscope.stats.norm.cdf" (`_getattr.py:67-68`).

Symmetry (`_symmetric.py`): `as_symmetric(data, *, symmetry)` validates with `np.allclose(array, array.transpose(perm), atol=1e-6, rtol=1e-5)` per non-identity generator and charges `k * (7n − 1)` (`_validate_and_charge_symmetry`, 339-369; `k` = non-identity generators, `n = data.size`), computed at `integer_to_float64_min_dtype(dtype)` (70-83; float32 stays float32), then **canonicalises** (copies one orbit representative, 0.12.1) and returns a `SymmetricTensor`; `is_symmetric` charges the same `k*(7n−1)` (386-437); `symmetrize(mode="reynolds-projection")` charges `(|G|+1)*numel` at `result_type(dtype, float64)` (float32 → float64 rate 2), `mode="canonical-copy"` charges `numel` at the input dtype (166-302); a bare `SymmetricTensor(data, symmetry=...)` is validated and charged like `as_symmetric` (806-852). Tagged operands: pointwise ops bill the orbit count, reductions are orbit-mapped, `inv` gets the symmetric formula, `eigh`/`cholesky` get no discount, contractions get output-orbit savings when the engine proves the output symmetric. **einsum path search gating** (`_einsum.py:358-412`): `_LARGE_K_THRESHOLD = 8`; for `k >= 8` operands only `optimize ∈ {"greedy","eager","opportunistic","random-greedy","random-greedy-128"}`, `False`, or an explicit list/tuple path pass verbatim; everything else (`"auto"`, `"optimal"`, `"dp"`, `True`, `None`, custom optimizers) is downgraded to `"greedy"` (path search runs unbilled in `flopscope_overhead_time_s`). `einsum(..., symmetry=...)` declares output symmetry (validated, `SymmetryError` on mismatch); `einsum(..., out=dest)` additionally bills a `copyto` of `numel(dest)`.

What is free: views/metadata (`transpose`, `.T`, `swapaxes`, `moveaxis`, `squeeze`, `expand_dims`, `broadcast_to`, `flip*`, `split*`, `diagonal`, 2-D `diag` extract, `real/imag`, shape/dtype introspection, basic `arr[int/slice/newaxis/...]` indexing — `_ndarray.py:835-`), untouched allocation (`zeros`, `zeros_like`, `empty`, `empty_like`), `asarray(x)` with no dtype change (billed from `np.may_share_memory`, `_array_ops.py:1775-1816`), `astype(x, dtype, copy=False)` when the dtype already matches, `load`/`from_dlpack`, `default_rng`/`seed`. NOT free: `reshape`, `ravel`, `copy`, `flatten`, `astype` (any real cast or same-dtype copy) bill `numel` at the heavier of source/destination rate (`astype`, 1674-1722, uses `_heavier_billing_dtype`); `concatenate/stack/tile/repeat` bill `numel(output)`; `ones/full` bill `numel`; `eye/identity` bill the diagonal length; `diag(v)` construct bills `v.shape[0]`; `triu/tril` bill kept elements (`_triangle_kept`, 1492-1510); `fill_diagonal` bills `min(m,n)` (or the wrapped count) (2707-2757); fancy/boolean `getitem` bills `4·numel(output) + numel(mask)`; `take` 4×numel; `.tolist()/.tobytes()/__array__` are outside the meter (cost-model.md "The meter boundary"). Dispatch overhead is never billed as FLOPs; it lands in `flopscope_overhead_time_s`, which is excluded from the residual gate.

## B2. Client/server architecture and BudgetContext API

Three distributions sharing the import name `flopscope` (`F:flopscope-client/README.md`): `flopscope` (in-process, full numpy backend — this IS the local backend; there is no in-process mode of the client), `flopscope-client` (numpy-free proxy; pyzmq + msgpack), `flopscope-server` (runs the real library; `pip install "flopscope[server]"` pins `flopscope-server==0.12.1`). Client and library are mutually exclusive in one environment.

Wire protocol: msgpack dicts `{"op", "args", "kwargs"}` over a ZMQ REQ socket (`_protocol.py:206-257`); first request does a `hello` handshake and refuses a server whose `X.Y.Z` version differs (`_connection.py:70-148`); every op response carries the server's authoritative `budget` (`{flop_budget, flops_used, flops_remaining}`), folded into the active client `BudgetContext` even on error responses (`_connection.py:247-260`; `_budget.py:191-209`). Arrays are created with `create_from_data(bytes, shape, dtype)` (`__init__.py:353-480`; nested lists, scalars, and any numeric buffer-protocol object incl. `array.array`/`memoryview`), returned as `RemoteArray(handle_id, shape, dtype, symmetry)`; `.tolist()`/`__float__`/`__array__` fetch the bytes; `__setitem__` and all in-place operators raise `TypeError` (immutable arrays, `_remote_array.py:821-879`); `.T` dispatches `transpose` (free). Server whitelist = registry ops + `{hello, budget_open, budget_close, budget_status, budget_summary, fetch, fetch_slice, free, create_from_data, __getitem__, astype, flops.einsum_cost, flops.svd_cost}` (`flopscope_server/_protocol.py:26-49`); `Generator.<method>` dispatch is limited to `_ALLOWED_GEN_METHODS = {uniform, standard_normal, normal, integers, random, standard_exponential, exponential, poisson, binomial, beta, gamma, choice, permutation, permuted, chisquare}` (`_request_handler.py:21-39`; `shuffle` excluded); RNG state lives server-side (handles `g0, g1, ...`), so `fnp.random.default_rng(mlp.seed)` is deterministic per seed. Client-unavailable names: 42 blacklisted (I/O, printing, iterators, `errstate`, `finfo/iinfo` registry entries, `random.random_integers`...), `fft.*` (the client `fft/__init__.py` is a stub whose `__getattr__` raises "registered but not yet implemented as a client-side proxy" for all 18 fft entries), `vectorize/frompyfunc`, the callback ops, and `SERVER_ONLY` names (`FlopscopeArray`, `SymmetricTensor`, `PathInfo`, `namespace`, `clear_einsum_cache`, all `flops.*_cost` helpers except `einsum_cost`/`svd_cost`, `_server_only_data.py`). `flops.configure()` is a no-op on the client (`ConfigureNoOpWarning`). Hardened image: `F:docker/Dockerfile.participant-hardened` (python:3.10-slim builder → `debian:trixie-slim`, stdlib stripped, no binaries except `python3.10`, `ENV FLOPSCOPE_SERVER_URL=ipc:///ipc/flopscope.sock`, entrypoint `entrypoint.py` runs `/submission/run.py`); `Dockerfile.server` (`pip install` library + server, `CMD python -m flopscope_server --url ipc:///ipc/flopscope.sock`); compose services `backend`/`participant` share an `/ipc` volume. No registry/tagged image names appear in either repo.

BudgetContext API (identical surface on both backends): `BudgetContext(flop_budget, quiet=False, namespace=None)` (+ `wall_time_limit_s=None` in-process only); context manager and decorator; properties `flop_budget`, `flops_used` (client: refreshed from every response — "not stale"), `flops_remaining`, `wall_time_s`, `flopscope_backend_time_s`, `flopscope_overhead_time_s`, `residual_wall_time_s` (live while open), `namespace`, in-process also `op_log` (list of `OpRecord(op_name, subscripts, shapes, flop_cost, cumulative, namespace, timing..., resolved_dtype)`); `summary_dict(by_namespace=False)` → `{flop_budget, flops_used, flops_remaining, operations{op:{flop_cost,calls,backend_s,overhead_s}}, wall_time_s, flopscope_backend_time_s, flopscope_overhead_time_s, residual_wall_time_s[, by_namespace]}`; `summary()` text. Module level: `flops.budget(...)`, `flops.current_budget()` → `BudgetSnapshot(flop_budget, flops_used, flops_remaining)`, `flops.budget_summary_dict(by_namespace)` (session/global, server-authoritative on the client), `flops.budget_summary()`, `flops.budget_reset()` (client: local cache only), `flops.accounting`/`flops.flops.einsum_cost(subscripts, shapes)` and `svd_cost(m, n, k)` (free shape-only estimators, proxied), `flops.flops.pointwise_cost(op_name, shape=...)`, `reduction_cost(...)` (local weighted estimates), `flops.remote_unsupported_ops()`. Client timing decomposition (`_budget.py:245-264`): `backend = server kernel_ns` (arrives with the close response), `overhead = dispatch − backend` (client-side accumulated dispatch time incl. wire + server marshaling), `residual = wall − dispatch`, each clamped ≥ 0; `wall` is `perf_counter_ns` since `__enter__`. Exceptions: `BudgetExhaustedError`, `TimeExhaustedError`, `NoBudgetContextError`, `UnsupportedDtypeError` (a `TypeError`), `UnsupportedFunctionError`, `RemoteCallbackError`, `RemoteSerializationError`, `UnauthorizedControlError`, `FlopscopeServerError`, `SymmetryError`; warnings `FlopscopeWarning`, `SymmetryLossWarning`, `CostFallbackWarning`, `RemoteCallbackWarning`, `ConfigureNoOpWarning`.

## B4. Pin and CHANGELOG

`W:pyproject.toml` pins `flopscope>=0.12.1,<0.13.0` (and `flopscope-server>=0.12.1,<0.13.0` in the `server` group), with the inline rationale: 0.12.1 "corrects ~40 prices that did not match what the operations actually compute — nan-prefixed reductions now charge their NaN-scan pass, six boolean-returning ops that compute in a promoted float dtype move by exactly 2x (this includes is_symmetric/as_symmetric, which bill allclose's formula), and einsum path search, multi-output ufuncs, fill_diagonal(wrap=True) and SymmetricTensor construction are repriced ... nothing already scored is repriced ... The floor is 0.12.1, not 0.12.0: 0.12.1 makes a symmetry tag describe the buffer it is attached to ... It also stops full/full_like inferring symmetry from shape when fill_value is not a scalar". `W:CHANGELOG.md` v0.16.1 (2026-08-29): "Raises the flopscope floor to 0.12.1" and publishes `mc_flops_per_sample()`; v0.16.0 (2026-08-21) set the Phase 2 defaults (1024x16, 2**41, lambda 0, 400 ms residual cap, 120 s predict cap, 8 GB cap, worker restart).

`F:CHANGELOG.md` **v0.12.1 (2026-08-29)**: `full`/`full_like` with a non-scalar `fill_value` no longer carry an inferred symmetry tag (measured +50% on `fnp.sin`, +55% on `fnp.einsum("ij,ij->")` for a (3,3) result built from a length-3 fill; scalar fills unchanged); `as_symmetric`/`SymmetricTensor` now canonicalise one orbit representative before attaching the tag (charges unchanged); `symmetrize` gains `mode="canonical-copy"` (bills `numel`, preserves dtype); Reynolds symmetrization refuses an unenumerable group at zero cost; internal tagging routes through `wrap_with_derived_symmetry`. **v0.12.0 (2026-08-21)** "ships as a new version opening a new phase, so no submission is re-evaluated against it".
