## 0. Round constants (from `whestbench.budget.CURRENT_ROUND`, tag `v2-phase2`)
- width=1024, depth=16, `predict()` returns `(16, 1024)`; read `mlp.depth`/`mlp.width`, never hardcode (Phase 1 was 256x32, warmup 256x8).
- `B_m = 2**41 = 2,199,023,255,552` FLOPs per MLP (Phase 1: 272,000,000,000; warmup: 68,000,000,000).
- `C_m = F_m` (λ = 0.0, `residual_mode='gated'`, `dtype_aware_billing=True`).
- Caps: predict wall clock 120 s/MLP; residual wall time 0.4 s/MLP (hard gate, zeros that MLP); `setup()` 5 s incl. module import, runs once per worker (~5–15x per submission), breach = `SETUP_TIMEOUT` fails the WHOLE submission; solution process 8 GB RAM; any single array 4 GiB on the grader (not enforced locally); 2 vCPUs pinned to the solution, 14 to the flopscope backend; no network, no GPU; 10 submissions/team/UTC day (resets 00:00 UTC, failures count).
- Suite: 100 MLPs graded (50 public drive the visible leaderboard + 50 holdout). Grader watchdog: finalizes when no MLP finished for 8 min OR 40 min total → unfinished MLPs = `WATCHDOG_TIMEOUT` (failed, x1.0); `truncation.reason="no_worker_capacity"` = grader fault, resubmit.
- Score: `adjusted_final_layer_score = mean_m [ final_layer_mse_m × max(0.1, C_m/B_m) ]`; any failure → that MLP scored as zeros with multiplier forced to 1.0 (10x worse than returning zeros successfully). Zero-prediction `final_layer_mse` ≈ 0.9095 on the Mini split (per-MLP adjusted spread 0.0567–0.1483). Below 10% of budget (219,902,325,555 FLOPs) the multiplier is pinned at 0.1 — every bundled example is at the floor, so only accuracy moves the score there.
- Default `ContestSpec` (`whestbench.cli._default_contest_spec()`): width 1024, depth 16, n_mlps 10, flop_budget 2199023255552, ground_truth_samples 200000, setup_timeout_s 5.0, predict_timeout_s 30.0 (only used when wall_time_limit_s is None; see runner note), memory_limit_mb 8192, wall_time_limit_s 120.0, residual_wall_time_limit_s 0.4, seed None, lambda 0.0.
- Fair accounting: packing independent values into one machine element (e.g. booleans into wide ints + bitwise ops) is prohibited even if metered; quantization/lower-precision dtype is fine. Rules questions / mispricing / residual-cap exception: arc-whestbench@aicrowd.com.

Report JSON goes to stdout (`--format json > report.json`).
- No `--width/--depth` on `whest run` (shape is the round default). No memory flag (8192 MB fixed in spec).

### Runner differences (`--runner`)
- `local`/`inprocess`: in-process; `pdb`/`breakpoint()` work (CLI pauses the live display; or `--format plain`; or `PYTHONBREAKPOINT=pdb.set_trace` auto-switches to plain); 8 GB limit is ADVISORY (prints `memory_limit_mb=8192 is advisory in --runner local`); wrong-shape `error_code` = `"ValueError"`.
- `subprocess`/`server`: one worker process over a stdin/stdout JSON pipe (the grader's transport). Catches dirty imports/sys.path reliance, stdout writes (stdout IS the IPC pipe — a `print()` in `setup()`/`predict()` desyncs the protocol and the run HANGS; use stderr/logging), values that don't survive JSON (predictions re-read with `fnp.asarray(..., dtype=fnp.float32)`), and runaway memory on Linux via `RLIMIT_AS` = 8192 MB (macOS refuses `setrlimit` silently → a Mac pass proves nothing about 8 GB). One worker serves the whole suite: `setup()` runs once, module imported once, globals/RNG NOT reset between MLPs. A worker that dies mid-suite is replaced (re-running `setup()`) and the suite continues. Response wait = `max(predict_timeout_s=30, wall_time_limit_s + 5.0 s grace)` = 125 s by default (whestbench <=0.14.0 gave up at 30 s). `error_code` = `"PREDICT_ERROR"`.
- There is NO docker runner. The only mention of Docker in the kit is CHANGELOG 2026-06-01 "remove the fictional Docker runner stage". The grader itself runs "an isolated subprocess inside a sandboxed container" with the flopscope *client* (a numpy-compatible proxy) talking to a backend, while local runs use the full flopscope package — client-only parity gaps (immutable arrays, `str` paths, 4 GiB array cap, missing numpy) surface only in grading.
- Sandbox imports: only `flopscope` (`flopscope.numpy as fnp`), the `whestbench` API (`BaseEstimator`, `MLP`, `SetupContext`), and the stdlib. No `requirements.txt` step; `--requirements/--submission-metadata/--approach` on package/submit are deprecated no-ops.

## 2. Packaging and submission
- Single file: `uv run whest package --estimator estimator.py --output submission.tar.gz` → archive = your file renamed to `estimator.py` + `manifest.json` (entrypoint, whestbench/flopscope/numpy versions, Python version, per-file SHA-256, timestamp). Default output `submission-<timestamp>.tar.gz`. Kit stub packages to 1.7 KB. If the single file imports a sibling module it REFUSES: `Error [package:PACKAGING_VALIDATION_ERROR]: estimator.py imports helper, which lives beside it and will NOT be bundled` (preceded by `⚠ Single-file submission: only estimator.py will be submitted. N items beside it will NOT be included: …`). Data files are only named in that warning, then dropped.
- Folder: `uv run whest package --estimator . --output submission.tar.gz [--yes|-y]` — requires `estimator.py` at the folder root (else `Folder submission requires an estimator.py in <dir>, but none was found`, also if an ignore pattern matches it); lists every file, sizes, asks `[y/N]`; warns about `.py` files not reachable by import from `estimator.py`; helper modules/`weights.npz` ship by presence and import with the same relative paths.
- Ignore rules: `.gitignore` + `.whestignore` read as ONE pattern list, gitignore glob syntax, NO `!` negation (a `.gitignore` entry matching `weights.npz` silently drops it). Built-ins: `.git/`, `__pycache__/`, `*.pyc` and credential files `_SECRET_IGNORES` (`.env`, `.env.*`, `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.keystore`, `*.jks`, `id_rsa*`, `id_dsa*`, `id_ecdsa*`, `id_ed25519*`, `.netrc`, `.pypirc`, `.npmrc`, `.aws`, `.ssh`, `.gnupg`, `credentials`, `credentials.*`). Kit's `.whestignore` excludes `.git/ .github/ .venv/ .python-version __pycache__/ *.pyc .pytest_cache/ .ruff_cache/ *.egg-info/ local_engine.py examples/ tests/ docs/ assets/ scripts/ Makefile README.md pyproject.toml uv.lock` (without it the repo is 64 files and trips the cap).
- Caps: 50 MiB total (CLI says ~52 MB) and 50 files. A (1024,1024) float32 = 4 MiB → a dozen fills the allowance; ship rank-k factors / calibration tables, not full matrices per layer. Sponsor may rule a "data" file to be a program (bytecode, serialized kernel, dispatch table).
- Verify: `tar tf submission.tar.gz` (estimator.py + manifest.json), `uv run whest validate-package submission.tar.gz`, `uv run whest submit --estimator . --dry-run` (packages to a tempdir, runs validate-package, prints files/sizes/resolved `flopscope==`/`whestbench==`, archive size; uploads nothing). Never hand-roll the tarball (manifest sha256 mismatch → `IMPORT_FAILED`).
- Pickle-free loading: `fnp.load` = `np.load(allow_pickle=False)` locally; the grader's flopscope-client parses `.npy/.npz` with its own codec and cannot unpickle (no `torch.save`/`joblib`/`pickle`). Author via `class Weights(flopscope.Module)` with PUBLIC array attributes (underscore attrs skipped), `w.save("weights.npz")` (flattens nested Modules/lists/tuples/dicts), reload `Weights.from_file(str(path))` — pass `str`, not `Path` (full flopscope accepts Path, the client does not). `fnp.load` = 0 FLOPs; `from_file` re-runs `__init__` so keep it to `fnp.zeros((), dtype=fnp.float32)` (free; `fnp.ones(())` = 2 FLOPs at float64). Inside `predict()`, `fnp.save/savez` bill egress ≈4 FLOPs/element × dtype rate; save offline with plain numpy instead.
- `setup(self, ctx: SetupContext)`: fields `width:int, depth:int, flop_budget:int, api_version:str, scratch_dir:Optional[str]=None, submission_dir:Optional[str]=None, seed:int=0`. `submission_dir` = folder containing estimator.py locally and the extracted root on the grader (guard `None`); `scratch_dir` is `None` on every 0.16 path — touching it raises inside setup and fails the whole submission (`base = ctx.scratch_dir or tempfile.mkdtemp()`). Allowed/intended: load files, unpack arrays, build data structures, `self.setup_rng = fnp.random.default_rng(ctx.seed)` and e.g. a `(ctx.width, 64)` random projection; its FLOPs are free (own flopscope session, billed to no MLP) and its wall time is not residual; NOT allowed in practice: training/heavy precompute (5 s cap, cold cache, runs 5–15x). Setup exceptions: local `Error [setup:SETUP_ERROR]: <msg>`, grader `SETUP_FAILED` → whole submission rejected. Also `teardown(self)` exists (lifecycle end).
- Submit flow: `uv run whest login` (prompts) or `whest login --api-key <key>` or env `AICROWD_API_KEY`; then `uv run whest submit --estimator estimator.py [--class X] [--yes] [--challenge arc-white-box-estimation-challenge-2026] [--description 'Submitted via whest submit'] [--watch] [--watch-timeout 600] [--dry-run] [--format json]` or `uv run whest submit submission.tar.gz`. `--watch` polls until graded/failed, detaching with a tracking link after `--watch-timeout` seconds. The portal upload of the tarball also works. Leaderboard = `adjusted_final_layer_score`; expect local Stage 4 ≈ leaderboard within ~1–2%; grader runtime "a few minutes".

## 3. Example estimators (exact structure)
Common scaffold: `class Estimator(BaseEstimator)`, `setup(ctx)` sets `self._setup_rng = fnp.random.default_rng(ctx.seed)`, `predict(mlp, budget)` starts with `_rng = fnp.random.default_rng(mlp.seed)`, returns `fnp.stack(rows, axis=0)`; `__main__` builds `build_mlp(width=1024, depth=16, seed=0)` and calls `compare_against_monte_carlo`.

- **01_random.py**: `rng.uniform(0.0, 1.0, size=(mlp.depth, mlp.width)).astype(fnp.float32)` wrapped in `fnp.asarray`; 131,072 FLOPs; `all_layers_mse` ≈0.52 and `final_layer_mse` ≈0.84 (default MLP, n=100k); Mini split: final 0.6856, all 0.5390.
- **02_mean_propagation.py** (diagonal Gaussian moment propagation):
  ```
  mu = fnp.zeros(width, dtype=fnp.float32); var = fnp.ones(width, dtype=fnp.float32)
  for w in mlp.weights:
      mu_pre = w.T @ mu
      var_pre = (w * w).T @ var
      var_pre = fnp.maximum(var_pre, 1e-12); sigma_pre = fnp.sqrt(var_pre)
      alpha = mu_pre / sigma_pre
      phi_alpha = flops.stats.norm.pdf(alpha).astype(fnp.float32)
      Phi_alpha = flops.stats.norm.cdf(alpha).astype(fnp.float32)
      mu = mu_pre * Phi_alpha + sigma_pre * phi_alpha
      ez2 = (mu_pre * mu_pre + var_pre) * Phi_alpha + mu_pre * sigma_pre * phi_alpha
      var = fnp.maximum(ez2 - mu * mu, 0.0)
      rows.append(mu)
  ```
  86,639,616 FLOPs (0.0039% of B_m). `all_layers_mse` ≈0.00017, `final_layer_mse` ≈0.00030 (default MLP, n=100k); Mini: final 2.216e-04, all 1.611e-04 (4,104x better than zeros). Final-layer MSE unchanged to 5 s.f. in float64.
- **03_covariance_propagation.py** (full covariance, "gain" ReLU update):
  ```
  mu = fnp.zeros(width, dtype=fnp.float32)
  cov = flops.as_symmetric(fnp.eye(width, dtype=fnp.float32), symmetry=(0, 1))
  log_scale = 0.0
  for w in mlp.weights:
      cov_diag = fnp.diag(cov); max_var_np = float(fnp.max(cov_diag))
      if max_var_np > 1e30: s = float(fnp.sqrt(max_var_np)); mu = mu / s; cov = cov / (s*s); log_scale += float(fnp.log(s))   # never fires at 1024x16: max diag stays in [0.26, 1.37]; costs 1,023 FLOPs/layer
      mu_pre = w.T @ mu
      cov_pre = fnp.einsum("ij,ia,jb->ab", cov, w, w)          # one contraction over symmetric-tagged cov → symmetric rate
      var_pre = fnp.maximum(fnp.diag(cov_pre), 1e-12); sigma_pre = fnp.sqrt(var_pre)
      alpha = mu_pre / sigma_pre
      phi_alpha = flops.stats.norm.pdf(alpha).astype(fnp.float32); Phi_alpha = flops.stats.norm.cdf(alpha).astype(fnp.float32)
      mu = mu_pre * Phi_alpha + sigma_pre * phi_alpha
      ez2 = (mu_pre*mu_pre + var_pre)*Phi_alpha + mu_pre*sigma_pre*phi_alpha; var_post = fnp.maximum(ez2 - mu*mu, 0.0)
      _zero32 = fnp.zeros((), dtype=fnp.float32)
      gain = fnp.where(sigma_pre > 1e-12, Phi_alpha, _zero32)   # explicit f32 zero keeps the where at f32 on 0.11 and 0.12
      cov = fnp.multiply(fnp.outer(gain, gain), cov_pre)        # cov_post[i,j] ≈ gain_i gain_j cov_pre[i,j]; keeps tag
      fnp.fill_diagonal(cov, var_post)                          # statement; voids the symmetry tag silently
      cov = flops.as_symmetric(cov, symmetry=(0, 1))            # re-validate → next einsum at symmetric rate
      rows.append(mu * float(fnp.exp(log_scale)))
  ```
  51,709,240,799 FLOPs (2.3515%); einsum 3,220,700,672/layer (99.66% of the total, 51,531,210,752 over 16 layers); `all_layers_mse` ≈0.000004, `final_layer_mse` ≈4.2e-06 (4.1674e-06 float32 vs 4.1676e-06 float64); Mini: final 4.050e-06, all 2.229e-06 (54.7x beyond mean propagation). 597x the cost of 02. Memory: O(width²) per covariance (4 MiB each at f32).

## 4. Every FLOP cost figure
Billing model (flopscope 0.12): `cost = flop_cost × weight × dtype_rate` (× complex factor); `dtype_rate` 1.0 for ≤32-bit, 2.0 for float64/int64, up to 4.0 for float128; NumPy promotion sets the billing dtype, one stray float64 upgrades the expression; `astype` bills at the DESTINATION dtype rate.
- Free (0): `fnp.zeros`, `fnp.empty`, views (`.T`, `fnp.transpose`, basic slicing/indexing `x[0]`, `x[:, 3]`), `fnp.asarray` on an existing flopscope array (no copy), `fnp.random.default_rng(seed)` construction, `fnp.diag`/`fnp.diagonal`, `fnp.load`/`Module.from_file`.
- 1 FLOP/element (× dtype rate): `add, subtract, multiply, divide, sqrt, maximum`, comparisons, `ones`, `full`, `eye` (only `min(m,n)` diagonal cells: `fnp.eye(1024)` = 2,048 at default f64, 1,024 at f32), `fnp.array()`/copying `asarray`, `.copy()`, `.astype()`, `reshape`/`ravel` (even where NumPy returns a view), `stack`, `concatenate`, `tile`, `repeat`; `fill_diagonal` = n (the one sanctioned in-place write); `outer(a,b)` = n×m.
- Reductions: `sum/max/min` = numel − n_outputs; `mean` = numel (sum + one divide per output).
- Transcendental 16/element: `exp`, `log`, trig, `x ** y` incl. `x ** 2` (write `x * x`). `sqrt` stays 1x.
- Gathers and 3-arg `where`: 4/element; sorts ≈ `4·N·ceil(log2 N)` (N=1000 → 40,000); `ix_` billed; einsum past the 52-letter subscript budget bills full FMA count; `where`/`insert` with a Python scalar use NEP 50 weak promotion (0.12). Non-numeric dtypes (`object`, `str_`, `bytes_`, `datetime64`, structured) raise `UnsupportedDtypeError` (a `TypeError`).
- RNG: `standard_normal` 16/element at float32, 32/element at the float64 default (`rng.standard_normal(1000, dtype=f32)` = 16,000); `uniform` calibrated per method (01's `uniform((16,1024))` at f64 + astype = 131,072 total).
- `stats.norm.pdf` ≈54/element, `stats.norm.cdf` ≈96/element (both promote f32 → f64 with a `FlopscopeWarning`; at width 1024: pdf 55,296/call, cdf 98,304/call); hand-rolled pure-fnp versions ≈20 (pdf) and ≈48 (cdf, Abramowitz–Stegun <7.5e-8, constants `_P=0.2316419, _A1..5 = 0.319381530, -0.356563782, 1.781477937, -1.821255978, 1.330274429`).
- matmul `(M,K)@(K,N)` = `M·N·(2K−1)` (random operands; structure discounts excluded): `(1024,1024)@(1024,1024)` f32 = 2,146,435,072 → `2**41` buys 1,024 of them (not 2,048); mat-vec `w.T @ mu` at 1024 = 2,096,128; `(10,256)@(256,256)` = 10·256·511.
- `fnp.einsum("ij,ia,jb->ab", cov, w, w)` at 1024 f32: 3,220,700,672 with symmetric-tagged `cov`, 4,292,870,144 untagged (saving 1,072,169,472 = 24.98%/layer); chained `w.T @ cov @ w` loses the tag (`SymmetryLossWarning`). `flops.as_symmetric(x, symmetry=(0,1))` bills `7n−1` per element pass with n = width² → 7,340,031 at f32 (2x at f64); 16 per-layer calls = 117,440,496 (0.23%), 17 incl. the redundant seed re-tag = 124,780,527; dropping the re-tag raises 03's einsum total from 51,531,210,752 to 67,613,752,832. `flops.symmetrize(mode="canonical-copy")` exists for large symmetry groups. 0.12 repriced (2x) `is_symmetric/as_symmetric, signbit, isneginf, isposinf, isclose, allclose`; `nan*` reductions pay the NaN scan; `angle` on bool 2x.
- Forward pass (MC sampling snippet, 1024x16, f32): 33,603,584 for one sample, 33,587,200 per additional sample (= 16·1024·2047 matmul + 16,384 relu + 16,384 mean + 16,384 RNG); 100 samples 3,358,736,384; budget ≈65,000 samples (`0.9*budget` headroom → ≈59,000). `local_engine.monte_carlo_layer_means` bills 33,637,376 per additional pass (float64 mean accumulation) → `2**41` ≈ 65,374 passes. MC table: n=10 → 336,439,296 (0.01 s); 100 → 3,363,803,136 (0.01 s); 1,000 → 33,637,441,536 (0.03 s); 10,000 → 336,373,825,536 (0.25 s); 100,000 → 3,363,737,665,536 (2.68 s, exceeds a whole per-MLP budget). Noise: MC error on a per-neuron mean falls as 1/N (CLI help) / accuracy as 1/sqrt(samples) (algorithm-ideas).
- 02 breakdown (16 layers): matmul 32 calls 67,076,096 (77.42%); multiply 128 calls 16,891,904 (19.50%; of which `w*w` = 1,048,576/layer = 16,777,216); `stats.norm.cdf` 16 calls 1,572,864 (1.82%); `pdf` 16 calls 884,736 (1.02%); astype 32 calls 65,536 (2,048 each = 1024 f64 elements × 2); add 48 calls 49,152; maximum 32 calls 32,768; sqrt 16,384; true_divide 16,384; subtract 16,384; stack 16,384; ones 1,024; zeros 0; total 86,639,616. Counterfactuals: drop f32 seeds only → 153,978,880; fully float64 (seeds + recasts dropped) → 153,913,344 (f32 seeding = 43.7% saving); letting the `stats.norm` f64 result flow onward reduces the saving to 2.7%.
- 03 counterfactual: all-float64 seeds 103,407,495,614 (49.99% saving from f32; not exactly 2x because the 32 `stats.norm` calls are f64 either way).
- Misc: `w.astype(fnp.float32)` on already-f32 (1024,1024) = 1,048,576/layer, 16,777,216 over 16 layers (weights ARE float32 on every construction path since 0.16.0); `fnp.ones(())` = 2 at f64, `fnp.zeros((), dtype=f32)` = 0; `fnp.sqrt(2.0/width)` scalar ≈2 FLOPs; 03 overflow guard 1,023/layer, 16,368 total; `fnp.save`/`savez` egress ≈4/element × dtype rate + headers; `ctx.deduct(op_name, *, flop_cost, subscripts, shapes, dtypes)` requires `dtypes=` (`()` for dtype-neutral; `(fnp.float64,)` doubles). `CostFallbackWarning` = flopscope over-charged (never under) a structure-priced op it couldn't bound. Phase 1 λ was 1e11 FLOP-equivalents per residual second.
- Memory (not FLOPs): one `(65,000, 1024)` f32 activation ≈270 MB (loop holds two); `(1024,1024)` f32 = 4 MiB, 16x the Phase 1 covariance element count.

## 5. Performance / wall-clock tips
- Grader: 2 pinned vCPUs for the solution, 14 for the flopscope backend; no hardware guarantee; rehearse with `--max-threads 1` (pessimistic bound) and `--residual-wall-time-limit 0.4 --max-threads 1`; `--max-threads` only pins the backend BLAS pool (timing knob); your own code may start no threads.
- Residual (400 ms hard gate, zeros the MLP, multiplier 1.0): everything not a metered op — Python loops/control flow, GC, I/O, Python-callback ops; since flopscope 0.7 data-movement ops (`concatenate, stack, tile, repeat, take, pad`) count as backend time, not residual. Biggest offender: a 1024-iteration per-neuron Python loop; vectorise into whole-array `fnp` ops; no `print()` in `predict()` (stdout flooding eats residual; in subprocess/grader it hangs the pipe); no `time.time()` deadlines calibrated to your machine (trips early on a slower grader and silently returns the fallback — prefer a budget-based cutoff using `budget` and `flops.budget_summary()`); move MLP-independent work into `setup()`; residual can be "several times larger" on the grader; anything near 400 ms locally is likely to fail there; `local_engine` prints a `RESIDUAL GATE` warning above 0.4 s. Measure with `uv run whest run --estimator estimator.py --profile` → `residual_wall_time_s` per MLP; `wall_time_s = flopscope_backend_time_s + flopscope_overhead_time_s + residual_wall_time_s` holds per MLP, aggregate, and per namespace. High `flopscope_overhead_time_s` = many small ops (per-call dispatch) → batch into bigger primitives.
- 120 s predict cap (`time_exhausted`); subprocess waits wall+5 s; grader watchdogs 8 min / 40 min; MLPs graded in parallel; an estimator sitting near the per-MLP cap on every MLP has no margin.
- Memory: 8 GB whole process (`RLIMIT_AS` in subprocess on Linux); 4 GiB single-array cap on the grader (`result array too large: N bytes exceeds 4294967296 byte limit`, also at smoke test) — process samples/rows/columns in blocks with running statistics; keep f32 (f64 doubles memory and FLOPs); count how many (1024,1024) covariances you hold; "reshapes and allocations cost 0 FLOP" per the FAQ (NB: `reshape` actually bills 1/element since 0.9 per the primer/test; allocation via `zeros` is free).
- Startup: `WHEST_SKIP_HARDWARE_FALLBACK_PROBES=1`; dataset runs skip MC sampling entirely; dataset-less `--n-samples 5000` ≈9x faster; `--n-mlps 3` while iterating, `20+` to reduce noise; `--seed N` for comparable generated runs; `--streaming` for tiny debugging runs only.
- Timings: Stage-1 five-row sweep ≈3 s; bake 10 MLPs @ 100k samples ≈80 s/670 MB; torch `--compile` ≈1.85x faster at width 256; `--chunk-size` on CUDA ≈25% of free VRAM clamped 65,536–1,048,576, MPS/CPU 65,536; lower `--mlps-per-batch` on OOM.
- Setup: time `setup()` on a cold cache; 5 s covers a file read and an unpack and nothing more; each worker re-pays it.
- Stay float32 (largest single reduction: ≈44–50% on the examples); cast `stats.norm` results straight back with `.astype(fnp.float32)`; a `float64` row in `ctx.summary()` reveals promotion.

## 7. Common errors → fixes
- Wrong shape (`expected_shape (16,1024)`, Phase-1 `(32,256)` constant, off-by-one depth±1, empty `(0, width)`) → return `(mlp.depth, mlp.width)` read off `mlp`; iterate `mlp.weights`.
- NaN/Inf → clamp/guard (`fnp.maximum(var, 1e-12)`), rescale covariance (03's guard) rather than widening to f64 (2x FLOPs); widen a single reduction and cast back if truly needed.
- `budget_exhausted`/`BudgetExhaustedError` (raised before the over-budget op executes) → `flops.budget_summary()`, reduce matmul/einsum, diagonal approximations; `combined_budget_exhausted` is a post-hoc backstop on the same count.
- `residual_wall_time_exhausted` (`ResidualWallTimeExhaustionWarning` locally) → move work into `fnp`, whole-array ops, MLP-independent work into `setup()`; ask organizers if structurally needed; verify `--residual-wall-time-limit 0.4 --profile`.
- FLOP counts jumped after kit update → flopscope repricing (0.9 four-factor; 0.10 `out=` priced + tag voided on write + einsum `out=` casting `TypeError`; 0.11 52-letter einsum FMA, `ix_` billed, `UnsupportedDtypeError`; 0.12 ~40 ops repriced); keep f32, `x*x`, check `ctx.summary()`; `uv sync` and re-measure.
- `result array too large … exceeds 4294967296 byte limit` (grader/smoke only) → block processing, f32.
- Class not found / `Ambiguous estimator classes … Pass class_name` → subclass `BaseEstimator` in the entrypoint; name it `Estimator` or `--class`.
- `IMPORT_FAILED`, manifest/api_version error, `'estimator.py' sha256 mismatch`, "tarball missing manifest.json" → never hand-roll; re-run `whest package`; `tar tf`.
- `ModuleNotFoundError`/`No module named 'numpy'`/`NameError: name 'np' is not defined` (swallowed import) → only flopscope/whestbench/stdlib on the grader; `import flopscope.numpy as fnp` (binding it to `np` is OK); helper modules need folder packaging; heavy work offline → `.npz`.
- Using numpy locally → `flops_used` = 0 (untracked); on the grader it fails; shipping numpy/scipy/BLAS/compiled kernels/ctypes/cffi/threads/asyncio/subprocess/multiprocessing, computing while a flopscope op is in flight, or touching the flopscope client/transport/accounting = disqualifiable (automated checks on every submission, agent-assisted validation, human review continuing after grading).
- Signature → `def predict(self, mlp: MLP, budget: int) -> fnp.ndarray`.
- `PREDICT_ERROR` panel, exit 1 → `--debug`, `--debug --fail-fast`.
- `SETUP_ERROR`/`SETUP_FAILED` → exception-proof `setup()`, load via `submission_dir`, reproduce with `--runner subprocess --debug`.
- `SETUP_TIMEOUT` (whole submission, one slot lost) → precompute offline, load in setup; rehearse `--setup-timeout 2.5`; `Error [setup:SETUP_TIMEOUT]: setup exceeded timeout (…)`.
- `PREDICT_TIMEOUT`/`TIME_EXHAUSTED` → infinite loop / too expensive; confirm `run_config.wall_time_limit_s`.
- `WATCHDOG_TIMEOUT` → partial = infrastructure, resubmit; all = hang.
- Dtype mismatch → `return fnp.asarray(result, dtype=fnp.float32)`; integer-dtype returns pass local checks silently, cast yourself.
- Immutable arrays (`item assignment … not supported`, `in-place add (arr += x) is not supported`) → `fnp.where(mask, v, arr)`, slicing + `fnp.concatenate`, `arr = arr + x`; `fnp.fill_diagonal(M, v)` as a statement (returns None).
- Reduction `axis=[0,1]` → `TypeError`; use a tuple.
- Every MLP failed (score ≈0.91 raw) → exit 1 + `failure_breakdown.error` = exceptions; exit 0 + all `budget_exhausted` / `combined_budget_exhausted` / `residual_wall_time_exhausted` / `time_exhausted` tell the rest apart. (Since whestbench PR #39 failures are finite, no `inf`.)
- Local great, submission 10x worse → (1) cross-MLP state/caches that are empty on the grader's several workers (make each `predict()` self-sufficient; don't use `scratch_dir`); (2) imports that only work locally or unshipped helpers; (3) unseeded randomness (use `mlp.seed`/`ctx.seed`, `--seed` locally); (4) unmetered work / residual timing on slower hardware (`flops_used` matches but `residual_wall_time_exhausted` fires). Then suspect Python/BLAS drift via `whest doctor`.
- Stage 4 worse than Stage 3 → `print()` to stdout (hang), shell-only imports, >8 GB on Linux (worker killed and replaced → partial regression), non-ndarray return.
- Reproducibility: seed `predict()` from `fnp.random.default_rng(mlp.seed)` (sub-streams via `master.bit_generator.spawn(3)`), `setup()` from `fnp.random.default_rng(ctx.seed)` (same value every setup call; `--seed`); never `fnp.random.seed(...)`; participant-chosen or time-based seeds may be disqualified for prizes; no filesystem reads outside `submission_dir`/`scratch_dir`; no network.
- Validate caveats: it does not time predict or check dtype; passes don't prove performance.

## 8. Algorithm ideas (docs/how-to/algorithm-ideas.md)
1. **Monte Carlo sampling** — `per_sample = 2*depth*width*width`; `n_samples = max(1, int(0.9*budget)//per_sample)`; `rng = fnp.random.default_rng(mlp.seed)`; `x = rng.standard_normal((n_samples, width), dtype=fnp.float32)`; per layer `x = fnp.maximum(fnp.matmul(x, w), 0.0); rows.append(fnp.mean(x, axis=0))`. Cost O(samples·depth·width²): 33,603,584 first sample, 33,587,200 each additional, 100 samples 3,358,736,384, ≈65,000 samples per budget (≈59,000 with the 0.9 headroom). Memory ≈270 MB per 65k×1024 f32 tensor, two live → chunk beyond. Accuracy ∝ 1/sqrt(samples); baseline/sanity check.
2. **Mean propagation (diagonal variance)** — O(depth·width²); 86,639,616 FLOPs (0.004%); cheapest reasonable start, baseline to beat, leaves the budget unspent.
3. **Covariance propagation (full matrix)** — O(depth·width³); 51,709,240,799 (2.351%), 597x mean propagation, still <3% and below the 10% floor so the extra FLOPs cost nothing in the compute term; use whenever accuracy justifies the effort.
4. **Fixed single-strategy design** — budget and shape are known up front; no runtime routing needed.
Open directions (untried by organizers): **Low-rank covariance** (rank-k factor `U (width,k)`, `cov ≈ U Uᵀ`, O(depth·width²·k), pick k from the early layers' covariance spectrum; ref: low-rank/Ensemble Kalman filter); **Layer-adaptive routing** (full covariance where correlations build, diagonal once roughly factored; use per-layer `all_layers_mse` plateau as crossover; full covariance for all 16 layers already fits in 2.4%, so it's about accuracy not fit); **Spectral / weight-statistics** (SVD of each W inside `predict()` — billed; can't hide the O(depth·width³) factorisation in `setup()` since weights don't exist there and setup is capped at 5 s; near-zero marginal cost after spectra; academic, sensitive to depth and He scaling; refs Pennington & Worah 2017, Saxe et al. 2014); **Importance sampling** (bias inputs toward high-variance deep-layer regions, re-weight `sum w_i·ReLU(...)/sum w_i`, O(samples·depth·width²) + proposal design; when MC plateaus above ~1/√samples); **Higher-order moments** (skewness/kurtosis per neuron, O(depth·width^k); corrects Gaussian pre-activation assumption asymmetry; ref Schoenholz et al. 2017). Code-patterns notes: Gaussian assumption exact only at layer 0; degrades for widths <~32, depth ~32+, and α≈0 regimes; 1024x16 is favourable. Low `final_layer_mse` with high `all_layers_mse` = assumption failure.
