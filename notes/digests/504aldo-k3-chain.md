## 1. The algorithm, layer by layer

### 1.1 Conventions, constants and embedded tables

From `docs/derivation_code_map.md`: n = 1024, L = 16, layer index li = 0..15; "unit" = one n x n x n matmul = 2 n^3 = 2^31 FLOPs, B = 2^41 = 1024 units; `w32` is the stored (n_in, n_out) matrix, `W = w32.T` so pre-activations are z = W h; d(v) = diag(v); `A * B` = Hadamard; `_zero_diag(X)` zeroes the diagonal in place (`fnp.fill_diagonal(A, 0.0)`).

Tables embedded at the top of every estimator (generated by `lean/dump_k3_tables2.py` from ARC's reference `mlp_kprop` combinatorics, pruned at relative contribution >= 1e-5: 62 of 90 terms kept):

### 1.2 State carried across layers (V25; V29 only changes buffer layout)

- Mean `mu` (n), covariance `C` (n x n, tagged `flops.as_symmetric(..., symmetry=(0,1))`), at each layer `C_pre`, `var = max(diag(C_pre), 1e-10)`, `C_off = _zero_diag(C_pre)`.
- Third cumulant as a sum of per-layer "sources" (one born per ReLU layer; k = li live). Per source s: dense legs `A_st[s]` (n x n) = P a_b (birth factor a_b = d(w1) C_off transported) and `P_st[s]` (n x n) propagator (born as the identity = W copied at first transport, then P <- W d(w1) P); thin transported leg `Z_st[s]` (n x (R_RES+2)) = P [3 Bm^T | u_b | y_b] with static right factor `L_st[s]` = [Q | w1^2 | 0]; thin feedback legs `Zf_st[s]` (n x 2 R_FB) = P [F1 | F2] with static right factors `R1T_st[s]`, `R2T_st[s]` (n x R_FB); static per-source vectors `w2b_list` (w2 at birth), `s_list` (S3c), `e_list` (e_b), `c1_list` (lam w1), `c2_list` (w1^2 dG), `y_list` ((m/4) w2), `dA_list` (9 + w2^2 + 9 e^2), `dP_list` (1 + S3c^2).
- Regenerated kappa4: scalars/vectors `g_prev` (post-ReLU diagonal core), `var_prev` (= K2v), `lam_prev` (table value, then adapted).
- Shared basis (old sources, slots [0:ka] of the stacks, oldest first): `Qc` (n x 384) transported, `FAo, FPo` (ka-kb, 384, n) static factors, `Sg` (384 x 384) weighted Gram core; nested tier (slots [0:kb]): `U` (384 x 224), `FA2, FP2` (kb, 224, n), `S2` (224 x 224), `QU = Qc @ U`.
- `newborn = (a_b, Rr_full, Lr_full, S3c, e_b, Ff_b)` produced at the end of a layer and consumed at the next layer's transport.
- Off-suite path only: `K4_sigma` scalar (isotropic kappa4), `K4_vec` (vec+ww rider, unused on suite).

`harness/dump_mini_mlps_p2.py`: reads the HF parquet shard `datasets--aicrowd--arc-whestbench-public-2026/snapshots/ce926b7d1ced65faa668c01b94a43f8c4f43783d/data/mini-00000-of-00007.parquet` with pyarrow, takes the first `N_DUMP = 8` rows (mlp ids 0-7 of the v2-phase2 `mini` split, 100 public MLPs), and writes `mlp_{mlp_id:04d}.npz` with `weights` (16, 1024, 1024) float32 (reshaped from `row["weights"]`, convention x @ w, i.e. columns = output neurons), `all_layer_means` (16, 1024) float32 (`row["all_layer_means"]`), `final_means` (1024) (`row["final_means"]`, asserted equal to `all_layer_means[-1]`), `avg_variance` (float64 `row["avg_variance"]`), `mlp_seed` (int64). The ground truth is therefore the dataset's own high-budget MC reference ("GT = all_layer_means from the official parquet = the scored high-budget MC ref", F46; "GT from 1e9 samples -> noise floor ~8e-11, 500x below everything measured", F43); the README's "~1e9 MC samples per MLP" refers to that reference, not to a computation in the harness. Dumps are ~62 MB each and not in the repo. Note the 8 dumps are 8 of the 100 mini MLPs and run ~6.5% above the LB raw at every version.

Per-layer true statistics in the repo: only `all_layer_means` (post-ReLU means per layer). True per-layer cumulants were NOT dumped; the per-layer MC diagnostics in F60 (`covprop_diag2.py`, ns = 3e5 samples: variance under-estimation -0.04% L1 -> -3.75% L16, std-skew ~1e-3, excess kurtosis +6.6% L16) and the `lam_obs_d0-7.npz` observables (chain-internal: mean_var, rms_Coff, mean_dG, mean_gprev, mean_varprev, mean_mu, rms_mu, mean_kurt, mean_absCoff per layer, collected with `V17_DEBUG=1` on `estimator_v24s.py`) are the only per-layer statistics; F16 points to keenanpepper's public dataset `huggingface.co/datasets/keenanpepper/arc-whestbench-higher-moments-2026` (O(W^2) moment tensors up to 4th order, pre and post activation, every layer, public MLPs) as a source of higher moments.

### 5.2 Measurement scripts
`harness/run_dumps.py` (uniform 8-dump runner): per dump builds `MLP(width=1024, depth=16, weights=[fnp.asarray(w.astype(np.float32)) ...], seed=0)`, `est.setup(_Ctx())` with `seed = 0`, then
```python
            with flops.BudgetContext(flop_budget=int(1e14), wall_time_limit_s=1200.0, quiet=True) as ctx:
                pred = est.predict(mlp, int(2 ** 41))
                C = float(ctx.flops_used)
            p = np.asarray(pred, dtype=np.float64)
            mse = float(np.mean((p[-1] - gt) ** 2))
            score = float(np.mean(gt ** 2)) if C > B else mse * max(0.1, C / B)
```
and prints C/B, mse, score, `ctx.residual_wall_time_s`. `test_v25.py`/`test_v16b.py` add `ctx.flopscope_backend_time_s`, `ctx.flopscope_overhead_time_s`, wall time, and sweep `AGE_OLD2:R_OLD2` or `R_RES`. `test_v29_gc.py`/`test_v29_knobs.py`: ONE estimator across several MLPs in one process (the way the suite runs), gc callbacks timing (`gc.callbacks`), Windows working-set via `ctypes.windll.kernel32.K32GetProcessMemoryInfo`, op-log retention (`keep.append(ctx)`), `len(ctx.op_log)`; knobs via env `V18_R_FB`, `V17_R_RES`. `audit_v29_ns.py`: runs `estimator_v29_ns.py` (33 `flops.namespace()` scopes inserted by `make_v29_ns.py`) twice (ledger on the second, steady-state call) and aggregates `r.flop_cost` of `ctx.op_log` records by `r.namespace` (first segment `Lnn` = layer, last segment = family), asserting the sum equals `ctx.flops_used`. `mem_v29.py`: peak working set after predict 1 (staged L4) and predict 2 (L5 pools). `parity_k3v3.py`: compares a port against `lean_v16p_pred_{i}.npz["pred"]` (lean prediction dumps) on `all_layer_means` (mse_final, mse_all, max|port-lean|). `run_v29_gate.sh`: mem check -> copy to `estimator.py` -> `uv run whest validate --estimator estimator.py` -> `uv run whest run --estimator estimator.py --dataset hf://aicrowd/arc-whestbench-public-2026@v2-phase2 --split mini --runner local`. Trap: `whest run` WITHOUT `--dataset` makes synthetic MLPs with a 200k-sample reference (noise floor ~4e-7) (F50).

### 5.3 The lean torch reference chain (for reuse on GPUs)
`lean/lean_k3.py` (K3-simple, V1.6 ablations, probes) and `lean/lean_k3_aug.py` (superset: + augmented r=1 kappa4 core, factored sources, confinement, regen hooks). Interface: `lean_k3_predict(weights: np.ndarray (L, n, n) in the x@w convention, dtype=torch.float64, statics=None, ...flags) -> torch.Tensor (L, n)` of post-ReLU means; internally `Ws = [torch.from_numpy(w.astype(np.float64).T).contiguous().to(dtype) for w in weights]`, `mu = zeros(n)`, `C = eye(n)`, `metric_c = 2.0`; `statics = build_static_coefs(n)` (computed once; `P2 = proj_coef(n, 4, 2)[2]`, `cA = 6/(n+4)`, `cS = 12/(n+4)`, `cI = -3/((n+2)(n+4))`). Dependencies: `torch`, `numpy`, and ARC's `mlp_kprop` package for the combinatorics at import (`from mlp_kprop.kprop_harmonic import get_all_terms_iso`; `from mlp_kprop.partitions import vec_part_coef, check_vec_partition, vector_partitions, int_partition_coef`; `from mlp_kprop.cumulants import _pK_to_K_coef`; `from mlp_kprop.harmonic import proj_coef, _multigraph_coef`; `from mlp_kprop.wick import _relu_wick_poly`) — the module builds `TERM_TABLE` (94 SIMPLE terms), `TERM_TABLE_AUG`/`TERM_TABLE_211`, `PK2K_TABLE(_AUG)`, `PK2K211_TABLE`, `WICK_POLYS` at import; to run without `mlp_kprop` one would embed the dumped tables (the estimators' `WICK_PAIRS/WICK_UNIFIED/TERM_SPECS/PK2K_TABLE` are the pruned 62-term version). `torch.set_grad_enabled(False); torch.set_num_threads(22)`; all tensors are created with `dtype=dtype` on CPU (no `.to(device)` plumbing — a GPU port needs device placement added; the code uses only matmul, Hadamard, `torch.linalg.eigh/svd/qr/svdvals/lstsq`, `torch.special.ndtr`, einsum). Key flags of `lean_k3_aug.lean_k3_predict`: `shadow_B2, shadow_B1, no_bprime, no_k3_feedback, no_wk22_fac` (V1.6 block ablations); `return_diag, svd_d21, d21_rank, tucker_rank, mean_corr, collect_feats, force_mean` (teacher forcing with true means); `age_rank=[(age, rank), ...]` nested tiers, `age_eig`; `debug_state` (per-layer G, K4v, K22, K31, K211_cap, contrib_a/b, mu, C, S3, S21). `lean_k3.py` additionally has `slice_keep` (memoryless slice closure, F65), `d21_corr`, `d3_corr`, `collect_d21`, `k3_snapshots`, `skip_birth` (F66). `reference_predict(weights, kind_name="SIMPLE"|"AUGMENT", return_G)` runs ARC's `mlp_kprop(mlp, K_in, k_max=3, kind=..., factor=True, output_all=True, up_to_layer=f"act{L-1}")` with `MLP(hidden_dim=n, num_layers=L+1, nonlin="relu", init_kind="manual", w_var=2.0)`; ## 6. Practical engineering facts
- Run time per MLP: local V25 ~20 s wall (grader ran V25 at 31-37 s/MLP; cap 120 s); V26 L3 26 s; V28/V29 36 s local; V16b/V17 14 s. The grader gives one physical core; "local 24-thread timings are meaningless for the caps"; 0.7-0.8 s residual seen only under 22-thread contention.
- Residual cap 400 ms per MLP: V29 steady 0.254-0.261 s, second-predict peak 0.33-0.34 s, local position-76 hiccup 0.72 s (V26 0.616, V28 0.718, V29 0.720 at the same suite position; in isolation 0.33/0.34 s) — a local harness artifact; the graded runs show 0 failures.
- Memory: V26 L3 peak 2.6 GB; V28 one-predict 3.4 GB (6.9 GB before pool-key/alias/fused-leaf fixes), two-predict 4.7 GB; V29 3.7 GB after the staged first predict, 5.5 GB after the second (L5 pools + 2 extra slots); limit 8 GB ("advisory in --runner local").
- Numerics: f32 hot path is lossless (f64: +0.004%, F88); Strassen f32 error 7.7e-7 (L1) to ~3-6e-6 (L5), MSE unchanged to 4 digits; port vs lean per-layer rms 1e-6 at L01 growing to 1.1e-4 at L15 (f32); deep chains amplify sum-order drift ~x300 at the last layer (F53), so parity tolerances must scale with depth; variance floor `fnp.maximum(..., 1e-10)`; clamp [0.5, 2] on the adaptive ratio prevents NaN -> zero fallback.
- Smoke-test shape trap: the grader's smoke test uses NON-suite shapes (depth 32 = the Phase-1 config, F50); a 16-row table indexed by layer threw IndexError and failed the submission (SETUP/ESTIMATOR_EXCEPTION, no quota cost); everything suite-specific is gated on `riders = (n == 1024 and L == 16)`, `r_old < n`, `r2 < r_old`, `min(R, n)`; smoke shapes tested locally: 64x6, 256x32, 64x16, 4x2, 128x20, 1024x3, 32x1 (bit-identical across V22/V24/V25 and at Strassen level 0); V1.6 is non-finite at 16x64 (pre-existing). Local `whest validate` smokes only at (2,4).
- 5 s setup cap fails the ENTIRE submission (F17); setup is off-budget/off-residual and runs 5-15 times; V29's `setup()` does only `fnp.random.default_rng(ctx.seed)` plus tiny warm-up calls (0.03 s); a full-size pool warm-up in setup was rejected because of the cap. Shipped data files: estimators are single files with embedded tables (LAM, REF_R, CORR_BETA, term tables); `flops.Module` packing (up to 50 MB / 50 files, loads at 0 FLOPs, F16/F26) exists but is unused in Phase 2 code; packaging gotcha: `whest package --estimator <file>.py` ships only that file (point it at the folder for sidecars).
- Grader facts: numpy is not installed at eval (only `flopscope` and stdlib); dataset weights arrive float64 (bill 2x) -> `astype(float32)` once; C > B is a zero-prediction fallback; public score = raw x C/B of the steady state; `whest run --split mini` reproduces the LB to ~5%; the first predict of a process is slower (pool warm-up) and is staged at L4 ("the grader's per-MLP compute is the steady-state number"; a process-per-MLP grader would pay the first-touch on every MLP, which the staging bounds at 0.33 s / 0.280 x B).
- Toolchain: flopscope >= 0.12 (0.12.1), whestbench >= 0.16 (0.16.1), dataset revision v2-phase2; `uv lock --upgrade-package` (plain `uv pip install` gets reverted by `uv run` sync).
- Methodology traps recorded: per-dump `EXTRA.pop()` bug class (a flag popped after the first dump); heredoc stdin not delivered to `run_in_background` commands (a generator patch silently did nothing); lambda tables must be fitted on the FULL chain (fits on ablated chains go negative at depth); validate compressions on the propagated state with compounding, never on a single-shot output truncation (F46); validate residual on a multi-MLP single-process run that retains op logs (F79); compare across versions by ratios (dumps vs LB offset 6.5%).
